# 5.9.3. Aplicación 3 — Política de inventario

Paquete `tss.modelo.inventario`, 6 clases. Compara dos políticas de
reabastecimiento sobre el mismo horizonte de demanda y entregas aleatorias.

## Resumen de clases

| Clase | Rol |
|---|---|
| `ParametrosInventario` | Niveles, costos y tabla Poisson del tiempo de entrega. |
| `PoliticaInventario` | Enum: revisión periódica vs. punto de reorden. |
| `SimuladorInventario` | Motor: recorre el horizonte día a día y decide cuándo ordenar. |
| `DiaInventario` | Traza de un día (llegadas, demanda, faltante, orden). |
| `ResultadoCorridaInventario` | Costos totales de una corrida completa. |
| `ResumenPolitica` | Promedios de muchas corridas para una política. |

## `ParametrosInventario`

```java
public record ParametrosInventario(
        int horizonte, int inventarioInicial, int nivelObjetivo, int puntoReorden,
        int periodoRevision, double costoMantener, double costoFaltante,
        double costoOrdenar, int ensayosDemanda, double thetaDemanda) {

    public static final double[] ENTREGA_ACUMULADAS = {
            0.0498, 0.1991, 0.4232, 0.6472, 0.8153, 0.9161, 0.9665, 0.9881, 1.0000 };

```

`ENTREGA_ACUMULADAS` es la tabla de tiempo de entrega Poisson(λ=3) del
enunciado, ya acumulada para usarse con transformada inversa.

`PoliticaInventario` sólo trae dos constantes con su descripción:


## `SimuladorInventario`

```java
public ResultadoCorridaInventario simularCorrida(PoliticaInventario politica) {
    for (int t = 1; t <= horizonte; t++) {
        inventario += llegadas[t];
        pendientes -= llegadas[t];

        int demanda = generarDemandaDiaria(uniformes);
        int faltante = Math.max(demanda - Math.max(inventario, 0), 0);
        costoFaltante += parametros.costoFaltante() * faltante;

        inventario -= demanda;               // puede quedar negativo
        if (inventario > 0) {
            costoMantener += parametros.costoMantener() * inventario;
        }

        int posicion = inventario + pendientes;
        int[] orden = evaluarReabastecimiento(politica, t, posicion, pendientes, llegadas);
        if (orden != null) {
            pendientes += orden[0];
            costoOrdenar += parametros.costoOrdenar();
        }
    }
    return new ResultadoCorridaInventario(politica, costoMantener, costoFaltante,
            costoOrdenar, total, ordenes, unidadesFaltantes, traza);
}
```

Cada día: recibe llegadas, sortea la demanda, cobra faltante o mantenimiento
según el saldo, y evalúa si toca ordenar. El inventario puede quedar
negativo (unidades pendientes de entrega): se cubre solo con la siguiente
llegada, sin lógica adicional.

```java
private int[] evaluarReabastecimiento(PoliticaInventario politica, int dia, int posicion,
        int pendientes, int[] llegadas) {
    boolean ordenar = (politica == PoliticaInventario.PERIODICA)
            ? (dia % parametros.periodoRevision() == 0)
            : (posicion <= parametros.puntoReorden() && pendientes == 0);
    if (!ordenar || posicion >= parametros.nivelObjetivo()) return null;

    int cantidad = parametros.nivelObjetivo() - posicion;
    int entrega = GeneradorVariables.indiceDeIntervalo(generador.uniforme(),
            ParametrosInventario.ENTREGA_ACUMULADAS);
    llegadas[dia + 1 + entrega] += cantidad;
    return new int[] { cantidad, entrega, dia + 1 + entrega };
}
```

Política 1 ordena por calendario (cada `periodoRevision` días); política 2
ordena cuando la posición de inventario baja al punto de reorden y no hay
ninguna orden en camino. Ambas piden lo que falta para llegar al nivel
objetivo y sortean el tiempo de entrega con la tabla Poisson.

corridas independientes para una política.
